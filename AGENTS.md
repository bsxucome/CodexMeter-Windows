# Windows companion development

This workspace contains an independent Windows addition for raycalrui/CodexMeter; see UPSTREAM.md for the missing upstream checkout and unverified commit baseline.

- Primary target: .NET 10, Windows 11 x64, WPF and NotifyIcon.
- A .NET Framework 4.8 compatibility build uses the same C# 5-compatible sources when no SDK is installed. Keep conditional JSON adapters isolated in Core/Json.cs.
- Keep platform/process code in windows/CodexMeter.Core; WPF lives in windows/CodexMeter.Windows.
- Core quota calculations, transport and service state must remain independently testable.
- Use Codex App Server over stdio. Do not read authentication files, copy tokens, store email, or expose raw server errors.
- Account boundaries immediately clear the UI and invalidate pending old responses.
- Read stdout and stderr concurrently with bounded memory. Own the child job and dispose it at exit.
- v0.3 adds opt-out local SQLite quota/token history under LocalApplicationData/CodexMeter. Partition accounts with a locally salted hash; never persist emails. Anonymous sessions must not merge across explicit account boundaries. Preview must never open the production database.
- Run windows/scripts/build.ps1 (Auto selects an available .NET 10 SDK, otherwise Framework); tests must pass before packaging.
- Use --smoke / --smoke --dark only for local preview artifacts; preview must not launch Codex or persist preferences.
- Update README, UPSTREAM and verification notes when public behavior or validation status changes.

- v0.2 adds a primary-taskbar overlay with real quota/time rings, safe gap calculation and saved visibility/position. Never describe it as native Explorer embedding; real Explorer docking is unverified in the isolated desktop.
- Keep the 380-wide popover compact with divider-separated rows, paired metric bars and content-measured height. Do not add the former oversized percentage cards.
- The popover hides its vertical scrollbar with ScrollBarVisibility.Hidden, not Disabled: wheel/touchpad/keyboard scrolling must remain available. Clip the middle viewport; keep the title and footer fixed. Do not apply this visibility change to independent history/settings windows.
- v0.4.2 gives the layered taskbar HWND a nonzero-alpha input background. Keep pointer handlers on the window so glyph gaps and border corners respond. Ordinary preview uses production transparency; only screenshot smoke uses a solid backdrop. Run indicator-smoke.ps1 sequentially with other previews. Release capture before queued popup activation, cancel gestures on capture loss, and preserve the popup generation check on deferred dismissal. Preview --interaction-check enables production dismissal without reading accounts or persistence.
- v0.2.1 adds StartLeft/StartRight/Auto/Custom docking. Start modes use the actual button bounds with a 4-DIP gap; blocked slots fall back above Start, never an unrelated gap. Legacy left ratios migrate to StartLeft.
- Keep the status indicator content-sized with 18-DIP rings. Use vector glyphs, tabular numbers and exact reset timestamps in the popover. Windows 11 backdrop material has an opaque fallback.
- UI smoke must leave an existing user instance running; skip normal-instance checks in that case and use isolated preview mode.
- v0.3 introduces five taskbar styles and popover content preferences. Hidden windows do not alter taskbar selection or historical recording. Deep-copy preference arrays. Localize UI via Core/TextCatalog and Windows/L; never transform user-entered paths. PowerShell scripts containing Chinese need a UTF-8 BOM for Windows PowerShell 5.
- Run ui-smoke.ps1, features-smoke.ps1 and --smoke captures sequentially: preview uses a shared mutex. Keep PARITY.md explicit about implemented, partial and pending upstream behavior.
- v0.4 uses local-time natural quota weeks/months and UTC service-date token buckets. Token and quota ranges are independent; annual tokens group by week, all data by month. Consumption is a lower bound when observations are incomplete. Estimates require at least three distinct monotonic points over 15 minutes with a two-point drop, fresh samples and a known reset beyond the estimate.
- Render quota cycles with a known 100% reset baseline, raw area and a display-only monotone smoothed dashed line. Shade long gaps; never persist synthetic points. Forecast segments still break across gaps, resets and replenishment.
- IndicatorView is shared by the taskbar and AppearanceWindow. Appearance JSON contains bounded appearance values only. Developer data is confined to independent preview controls/windows. Add advanced-smoke.ps1 to sequential UI checks. Never rebuild a history selector while its dropdown is open unless an account boundary requires immediate clearing.
- v0.5 optional Credits and ResetCredits are read-only state from rate-limit responses. Missing is not zero; the summary count is authoritative, expired/consumed detail rows are omitted, invalid lifetime intervals never produce bars. Never redeem resets or persist their opaque IDs. Clear these fields and rotate the in-memory notification SessionId on account boundaries even when history is disabled.
- SectionOrder is bounded to Quota/Credits/Resets/History/Tokens; visibility/order never changes collection. Horizontal uses parallel bars, Stacked includes paired bars and Q/T, Percentage omits its caption, Progress omits all numeric text. Flash only changed digits, not the percent sign.
- QuotaCycle normalizes reset jitter and continuously observed unused sliding windows in storage and old-row rendering. CycleResetsAt anchors history only; retain the official ResetsAt for quota/countdown. Seed a fresh service's anchor from the current account's latest stored sample when available.
- QuotaNotifications is pure and opt-in; only fresh completed snapshots trigger transition alerts. Scope by SessionId and window, enforce cooldown, merge simultaneous low/pace alerts, and revalidate queued alerts before ShowBalloonTip. Preview never sends notifications. Actual system delivery depends on Windows notification settings.
- StartupRegistration updates only the current user's CodexMeter Run value, only after an explicit saved checkbox change. Re-read actual registration when opening Settings. Observe StartupApproved conservatively, report unknown layouts, never write it or override a system disable. Preview uses no startup registry access; tests inject an in-memory store. Roll back the exact prior Run command if settings persistence fails.
- Taskbar native bounds must update independently of Explorer UI Automation. Keep at most one UIA probe in flight; compare handle/bounds/DPI before applying a result. Fullscreen detection uses DWM visible bounds on the taskbar monitor and excludes known shell surfaces. Display changes, session unlock, resume and TaskbarCreated invalidate placement. Real Explorer/mixed-DPI acceptance remains pending.
- v0.6 remote reminders are opt-in and require an actually observed fresh increase, never a predicted reset. Keep secrets in current-user DPAPI only, fail closed when unavailable, mask inputs and never expose raw provider errors. Bound retry/queue/response sizes; cancel obsolete account work and do not replay ambiguous delivery outcomes. Preview never sends messages or reads the vault.
- Backups contain only exact SQLite history and manifest entries, including identity salt and all accounts. Validate structure/integrity/hash/counts, create a pre-restore backup, pause service history writes, rollback failed replacements and re-identify accounts before recording again. Preview never opens production backups or history. Keep deletion confirmation for actual user-initiated destructive actions.
- Windows updates require configured HTTPS feed and RSA trust key, signed runtime/channel/product/version policy, exact archive/file hashes and safe paths. No upstream macOS packages or invented production keys. Install into a new sibling directory, verify helper readiness before exiting, keep the old executable for startup rollback, and migrate only an existing exact startup path without touching StartupApproved. Include release-smoke.ps1 in sequential UI checks. Local process handoff, DPAPI and hosted release acceptance must remain explicit in verification notes.
- v0.7 restore journals are bounded, basename-constrained and validated before opening SQLite. Prepared replacement recovery restores the original verified database; committed recovery keeps the validated new one. Never silently discard corrupt recovery evidence or a file owned by another process. Keep real child-interruption coverage.
- History drawing may reduce display points within each actual cycle/segment only; do not mutate raw observations, invent gaps or reduce hover precision. Cache invalidation must include account and database revision; open selectors must retain their state.
- Remote window switches, Bark icon and Gotify priority belong in the encrypted profile. Reserve weekly quotas default hidden unless explicitly configured; never change collection or taskbar selection with that default.
- Update-process integration fixtures require the explicit GUID root and marker, use isolated preview state and own every process they stop. Run update-process-smoke.ps1 sequentially with UI previews. No fixture may access production history, startup registration or credentials.
- ProductVersion.Current is the release version authority; keep SDK metadata and manifest aligned. GitHub publishing must scan staged source, exclude local data, refuse unrelated existing remotes and avoid force pushes. Publish no production signing key or credential. A prepared workflow is not a successful hosted build or deployment.
