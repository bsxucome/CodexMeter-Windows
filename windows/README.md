# CodexMeter for Windows · 使用与构建指南

[项目中文首页](https://github.com/bsxucome/CodexMeter-for-Windows#readme) · [English overview](https://github.com/bsxucome/CodexMeter-for-Windows/blob/main/README.en.md)

设置页已隐藏右侧滚动条并保留滚动功能。“弹窗区域顺序”和“额度窗口显示与顺序”列表内可使用滚轮；内容无需内部滚动或已到边界时，滚轮继续滚动外层设置页。列表选择、排序操作与键盘翻页保持可用。

支持 Windows 11 x64。默认在主屏幕任务栏区域显示双环＋百分比：外环是剩余额度，蓝色内环是剩余时间。点击展开详情，拖动调整位置，右键可重置位置、设置或退出。详情按原项目采用 380 宽度、紧凑字号、分隔线、矢量图标、成对进度条和精确重置日期；Windows 11 上启用系统弹窗背景材质，不支持时使用纯色。系统托盘入口继续提供快捷操作。

## 运行

1. 安装 Windows 原生 Codex CLI 并在终端运行 `codex login`。
2. 解压便携包的全部文件，运行 `CodexMeter.exe`。
3. 在任务栏区域查看双环和百分比。也可从系统托盘圆环入口进入设置。CLI 路径留空自动查找；找不到时选择 codex.exe 或 npm 的 codex.cmd。
4. 可用 `CodexMeter.exe --show` 启动并立即显示详情。再次运行会请求已有实例显示详情。

应用优先使用 npm 包内的原生 codex.exe，不执行 codex.ps1，也不修改 PowerShell 执行策略。无原生包时可使用 Node 和官方 codex.js 入口。普通任意 cmd/bat 脚本不受支持。

两种发布：
- `CodexMeter-Windows-0.7.0-dotnet10-x64.zip`：推荐的 .NET 10 自包含包，不需要单独安装 .NET。
- `CodexMeter-Windows-0.7.0-framework-x64.zip`：兼容包，使用 .NET Framework 4.8 或更新版本。

两种便携包均已在 [0.7.0 发行页](https://github.com/bsxucome/CodexMeter-for-Windows/releases/tag/windows-v0.7.0) 提供，并附 SHA-256 校验文件。

暂不支持 WSL CLI、ARM64。API Key / Bedrock 等账号可能不提供 ChatGPT 额度与 Token 活动；不存在的数据不会被显示为零。安装在桌面应用私有位置的 Codex 需要手动指定路径，不保证与独立 CLI 自动共享登录状态。完整功能对齐状态见 [PARITY.md](PARITY.md)，当前仍是分阶段移植。

- 新增 GitHub 浏览器授权建仓脚本、干净源码 ZIP、官方 SDK／GitHub CLI 校验下载脚本、上游提交采集脚本。双运行时 CI 在版本标签上发布经过哈希检查的 Release，可用自有密钥附加签名更新源。

## v0.6.0 新增

- 设置页与主面板统一为 380 DIP、16 DIP 内边距、14／13／12／11 字号和分隔线；固定标题和保存栏，内容区使用无箭头的细滚动条。远程、备份与关于窗口沿用同一布局。
- 设置 → 远程补充提醒：Bark、Gotify、Telegram、Discord 独立启用、凭据清除、测试和最近状态。仅在两分钟内连续观测到额度实际回升时提醒，同一窗口冷却五分钟；初次读取、切换账号、过期或观测空档不猜测补充。账号变化取消排队与重试。429／5xx 最多三次，每次超时八秒、退避不超过三十秒；网络中断等结果不明确时不盲目重发。
- 渠道配置由当前 Windows 用户 DPAPI 加密到 `remote-secrets.bin`；普通设置、历史备份与日志不含渠道凭据。加密不可用时拒绝保存，不退回明文。Bark／Gotify 支持 HTTPS 服务及本机 HTTP，Discord 只允许官方 Webhook，关闭 mention 解析。
- 设置 → 备份、恢复与账号管理：导出 `.codexbackup`，使用 SQLite 一致性快照，包含所有账号的额度、每日 Token 与身份盐，排除偏好和登录数据。备份不是加密文件，请按个人使用记录保存。恢复前校验格式、结构、完整性、SHA-256 与计数，并显示账号／记录数量；暂停采集后自动保存旧库备份，替换失败回滚，重新识别账号后恢复采集。现有保留期限继续适用。
- 恢复前备份位于 `%LOCALAPPDATA%\CodexMeter\backups`。可管理当前／其他匿名本地分区，清除所选或全部账号历史；清除不删除身份盐，后续采集仍按设置继续。
- 设置或托盘 → 关于与更新：支持 Stable／Beta、可配置清单地址与 RSA 公钥、手动检查／下载／安装，以及独立选择每日检查和空闲时自动安装。下载后及辅助进程安装前均校验签名、运行时、包哈希、文件清单与逐文件哈希；只接受新版本 Windows 包，禁止路径穿越、链接与未列出文件。
- 安装到新的同级目录，保留旧版本与 `%LOCALAPPDATA%` 数据；辅助进程准备就绪后才退出旧版。新版需在三十秒内启动界面并持续存活两秒，否则终止本次启动的子进程并尝试重启旧版。正常工作后发生的崩溃不在这段启动回退窗口内。自动更新仅在没有打开面板或管理窗口时安装；需对应用同级目录有写入权限。
- Windows 公开发行仓库已建立；正式代码签名证书和更新签名密钥尚未配置，因此更新地址／可信公钥保持空白，自动选项默认关闭。发布、签名与 CI 接入见 [RELEASES.md](RELEASES.md)。当前提供未做 Authenticode 签名的便携包。

远程实际投递、正常用户会话中的 DPAPI 和线上更新源仍需实机验收。v0.7.0 已补真实辅助进程交接及启动回退测试；HTTP、SQLite、RSA 与进程测试均隔离，不发送真实消息、不替换用户运行中的版本。

- 登录启动使用当前用户 Run 注册项，无需管理员。仅保存时明确改变开关才更新；打开设置会重新读取实际注册路径，识别已知系统禁用标记，未知状态明确提示。不会覆盖 Windows 的启动禁用选择；可跳转系统启动应用设置。便携目录变更后需要在新版设置中重新启用以更新路径。

## v0.4.0 新增

- 额度历史支持日历周／月翻页、返回本期和全部历史；不会翻到未来或最早保留记录之前。日历边界采用本地时区并考虑夏令时。F11 切换全屏，Esc 退出全屏。
- Token 范围独立选择 7／30／90 天、一年或全部数据；一年按周、全部按自然月汇总。缺失日期仍留空，悬停可查看汇总区间、精确总数和有记录的天数。

- 每个重置周期独立绘制；已知周期起点以 100% 为基准，面积使用原始采样，虚线仅做单调平滑显示。超过 30 分钟的未记录区间用阴影标示，平滑曲线及中间点不写入数据库。预测不会跨越这些空档。
- 弹窗加入当前标准周额度小图，可单独关闭，并链接完整历史窗口。
- 设置 → 高级外观：双环尺寸和粗细、字号、间距、横条宽度、名称开关和时间颜色；默认／紧凑／醒目预设；有界 JSON 导入导出。高级窗口里点“应用到设置”，再在设置中保存。
- 高级外观使用独立演示额度／时间滑块、常见状态和 30 天历史预览，与正式账号和历史隔离。实际任务栏与预览共用绘制组件，颜色也用于弹窗时间条。
- CSV 依照额度和 Token 各自选定的范围导出，增加原始 Unix 秒及带偏移的本地 ISO 时间。

## 任务栏显示

任务栏显示默认启用，已有 v0.1 设置也会自动启用。可在设置中关闭，或选择它代表的额度窗口。位置会保存；右键显示条可选择紧靠 Windows 开始按钮左侧／右侧或自动靠右，设置里也可切换。左侧旧位置在升级时自动迁移到开始按钮左侧。

实现为独立、无激活的透明停靠浮层，跟随 Windows 任务栏的明暗主题。它通过 UI Automation 读取按钮边界，优先安放在空白区域；没有可确认的空位时停靠在任务栏上方。不会修改 Explorer 布局或注入 Explorer 进程。拖动靠近开始按钮时会吸附到对应一侧，以按钮实际边界为锚点保留 4 DIP 间隔。此处空位不足时显示在按钮附近上方，不会跳到远处。自由拖动时仍按可用空位定位。显示条采用 18 DIP 双环，并按数字宽度收缩，去掉多余横向留白。

当前支持主屏幕的水平任务栏。全屏、自动隐藏和 Explorer 重启的处理逻辑已实现，但测试桌面没有可访问的 Explorer 任务栏，因此实际停靠、多显示器和这些系统交互尚需实机验收。预览截图只证明显示条的外观，不代表已验证真实任务栏嵌入。

## 数据与刷新

通过本地 `codex app-server --listen stdio://` 通信。客户端调用初始化、account/read、account/rateLimits/read 和可选的 account/usage/read；认证由 Codex 自己处理。后台默认每 60 秒、详情展开时每 10 秒刷新额度；Token 默认每分钟查询一次，手动刷新也会查询。请求不重叠。失败退避最长 5 分钟，保留最近成功结果并标记过期，手动刷新可立即重试。Token 查询最多额外等待 5 秒，额度成功结果会先显示。

每次刷新先检查账号；明确账号切换会立即清除旧显示，并拒绝旧请求返回的数据。窗口计算使用服务返回的实际时长，不硬编码必须存在五小时和周额度。缺失时间不估算；倒计时本地每 15 秒更新。托盘默认优先标准周额度，否则使用剩余最低窗口；用户可以指定其他窗口。

保存 `%LOCALAPPDATA%\CodexMeter\settings.json` 和默认启用的 `history.sqlite3`（含 SQLite 日志文件）。历史保存额度采样、每日 Token 数量以及本地加盐账号标识；不保存邮箱、密码或访问令牌。缺少稳定账号身份时按会话分区，明确账号边界后不会合并匿名历史。可在设置中停止新增记录；历史存储故障不会阻断实时额度。

不读取认证文件、不抓取网页、不发送遥测、不显示原始错误或 stderr。Codex 自身仍可能执行其正常的配置读取、联网和认证更新。输出行上限 1 MiB，stderr 仅保留最多 8 KiB 内存尾部，不展示或写盘。退出通过 Windows Job Object 清理自有子进程。

## 构建与验证

默认构建不依赖第三方 NuGet 包。测试是独立控制台测试程序，失败返回非零退出码。

SDK 的 Core、Tests 与 WPF 项目均以 Windows 为目标；保留平台分析器和警告即错误检查。Framework 管道启动会避免 UTF-8 控制台引入 BOM，并恢复父进程的原编码，JSON 帧始终按无 BOM UTF-8 传输。自动测试包含实际子进程的中文／Emoji 逐字节响应。

```powershell
# 从项目根目录运行；只对当前构建进程设置脚本策略
powershell -NoProfile -ExecutionPolicy Bypass -File windows/scripts/build.ps1

# 生成便携 ZIP；自动选择本机可用的 .NET 10 SDK，否则使用 Framework
powershell -NoProfile -ExecutionPolicy Bypass -File windows/scripts/build.ps1 -Publish

# 明确选择 .NET 10 自包含发布
powershell -NoProfile -ExecutionPolicy Bypass -File windows/scripts/build.ps1 -Runtime DotNet -Publish
```

.NET 10 SDK 可系统安装，或运行 `windows/scripts/setup-dotnet.ps1` 校验下载到项目 `.tools/dotnet/`（dotnet.exe 在该目录下）。不会修改现有系统运行时。构建产物在 `windows/artifacts/`。

若已有程序正在使用构建目录，可给 Framework 构建或发布命令添加 `-ArtifactDirectory "D:\Codex Project\CodexMeter\windows\artifacts\appearance-fix"`，将新产物放到独立目录，避免覆盖运行中的程序。

```powershell
# Framework 构建的测试与真实额度诊断（仅输出窗口数量和安全错误）
& windows/artifacts/CodexMeter-framework-x64/CodexMeter.Tests.exe
& windows/artifacts/CodexMeter-framework-x64/CodexMeter.Tests.exe --probe 'C:\path\to\codex.exe'

# 本地演示，不启动 Codex、不写设置或正式历史；--smoke 保存截图后退出
& windows/artifacts/CodexMeter-framework-x64/CodexMeter.exe --preview
& windows/artifacts/CodexMeter-framework-x64/CodexMeter.exe --smoke --dark
```

预览图保存在应用目录下 screenshots/。加上 --settings、--history 或 --appearance 可预览相应窗口；--english／--traditional 预览其他语言；--style=Horizontal／Stacked／Percentage／Progress 切换显示条样式。预览数据与真实账号无关，界面明确标记。预览与截图脚本需串行运行，避免共享预览实例。
